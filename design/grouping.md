# «Группировка по дате» — проект и реализация (V3)

**Статус:** реализовано (2026-11-17). Основание: спека [design/spec](spec/README.md) v1.5, канонический макет [`design/artifacts/variant-c.html`](artifacts/variant-c.html) (`#columns` с группами), референс Dolphin [`reference/dolphin-spec.md`](reference/dolphin-spec.md) §4.2, §10. Продолжение итераций [view-panel.md](view-panel.md) (§10.2) и [view-modes.md](view-modes.md) (§12.1).

**Предмет:** разбиение листинга на группы по дате изменения во всех трёх режимах, секция «Группировка» в панели «Вид» и хранение выбора.

**Не предмет (эта итерация):** пресеты, масштаб (zoom), фильтр, выделение, инспектор; сворачивание групп; «Настроено вручную»; псевдо-сканирование при смене группировки.

## 2. Ключевые решения

### D1. Ядро назначает корзину и день; подписи живут в `display`

`core/order.py` остаётся про календарную арифметику (`group_of`, `day_start`), `core/model.py` — про состав групп. Русские подписи — данные отображения (тот же приём, что `ViewMode.label` и `MODE_ORDER` в [display/settings.py:24](../src/volna/display/settings.py), D8 в view-modes).

`Group` получает `day` — локальную полночь дня записи (или `None`):

```python
# src/volna/core/model.py
@dataclass(slots=True, frozen=True)
class Group:
    bucket: GroupBucket
    entries: list[Entry]
    day: float | None = None   # локальная полночь дня; задана только для THIS_WEEK
```

Почему не строка-подпись в ядре: ядро не знает про локаль UI, а подписи тестируются без GTK; D8 уже принят в проекте.

### D2. Подписи: Сегодня / Вчера / день недели / Неделю назад

| Корзина | Условие (`group_of`) | Подпись | Источник |
|---|---|---|---|
| `TODAY` | `mtime >= сегодня 00:00` | `Сегодня` | спека 04 §6.2, макет `c1` |
| `YESTERDAY` | `>= сегодня − 1 сут` | `Вчера` | макет `c2` |
| `THIS_WEEK` | `>= сегодня − 7 сут` | **имя дня недели**: `Среда`, `Вторник`, … | макет `c3`, `c4` |
| `OLDER` | иначе | `Неделю назад` | макет `c5`, спека 05 §4 |
| `UNKNOWN` | `mtime is None` | `Без даты` | выведено из макета-прототипа; в референсе не встречается |

Разбиение `THIS_WEEK` по календарным дням:

- макет показывает **по группе на день** («Среда» = 11.11, «Вторник» = 10.11), а не одну группу «На этой неделе»;
- ядро уже документирует, что подписи дней рисует UI поверх `THIS_WEEK` ([core/order.py:18](../src/volna/core/order.py));
- окно — скользящие 7 суток от текущей полуночи: `day_start(now) − 7·86400` (границы — существующий `group_of`, не меняем).

Порядок групп: `BUCKET_ORDER`; внутри `THIS_WEEK` — дни от новых к старым. `UNKNOWN` — в конце.

`«Ранее»` из домашней группы макета (`h3`) не берём: спека 04/05/08 и референс называют последнюю корзину `«Неделю назад»`; расхождение макета фиксируем здесь.

### D3. Сортировка внутри групп — уже работает, ядро не меняется

`DirModel._flush_order()` сортирует весь список, `groups()` лишь раскладывает его по корзинам, сохраняя порядок. Значит «сортировка действует внутри группы» (05 §5) выполняется без правок: имя/размер/дата — внутри группы, `folders_first` — тоже внутри. Тест фиксирует это свойство.

### D4. Контракт `Section` не меняется

Заголовок — строка, счётчик выводится из `len(section.items)`. Виды сами рисуют заголовок (у каждого режима своя раскладка заголовка — D5–D7), поэтому виджет-фабрика заголовка не входит в контракт.

```python
# src/volna/views/base.py — без изменений по смыслу
@dataclass(frozen=True, slots=True)
class Section:
    items: tuple[ListingItem, ...]
    header: str | None = None
```

Плоский случай по-прежнему одна секция `header=None`: «Подробности»/«Значки» рисуют те же компоненты без заголовков, «Столбцы» — безголовые колонки по 6 строк.

### D5. «Подробности»: строки-заголовки в гетерогенной модели `ColumnView`

`Gtk.ColumnView` уже даёт липкую шапку колонок («Имя / Размер / Дата») — её не трогаем. Групповая строка — элемент той же модели:

- хранилище: `Gio.ListStore.new(GObject.Object)`, элементы — `ListingItem` **или** `GroupRow(label, count)` (новый GObject в `views/details.py`);
- фабрика имени: для `GroupRow` — `label` + `count` в `.volna-dt-group` (28 px, фон `#26282d`, линии сверху/снизу — 04 §6.2);
- числовые колонки: для `GroupRow` — пустая ячейка с тем же фоном (фон строки должен быть непрерывным, проверено пробой);
- активация (`activate`) игнорирует `GroupRow`;
- неоднородные высоты строк в `ColumnView` работают (проба `.tmp/grouping-probe/column.png`: 28 px заголовок + 24 px строки).

Альтернатива «свой `ListView` на секцию» отвергнута: теряется липкая шапка колонок и шаринг ширин.

### D6. «Значки»: вертикальный `ListView` из заранее нарезанных строк

`Gtk.GridView` не умеет заголовки секций (нет `header-factory`; section-API GTK 4.12 не используем — пол GTK остаётся 4.0). Решение — тот же приём, что у «Столбцов»: **виртуализация по строкам**:

- в режиме `grouping=date` вид показывает `Gtk.ListView` (вертикальный) вместо `GridView`;
- модель — `Gio.ListStore` элементов-строк: `HeaderRow(label, count)` (28 px) и `TileRow(items)` — до `N` плиток в строке;
- `N` считается от фактической ширины полосы: `N = max(1, floor((width + gap) / (_TILE_MIN + gap)))`; ширина плитки — `clamp((width − (N−1)·gap) / N, 150, 178)` (базовые px через `px()`), то есть плитки фиксированной ширины, а не растянутые на всю полосу: короткая группа не должна превращать две плитки в полосы по полэкрана. Остаток ширины остаётся справа (у макета его раздаёт `space-between` — приближение, ОД-3);
- строка-полоса — свой `Gtk.Widget` (`TileBand`) с ручной раскладкой: у GTK есть только *минимальная* ширина запроса, и обычный `Gtk.Box` заморозил бы минимальную ширину окна на текущей ширине полосы, из-за чего ресайз и пере-нарезка стали бы невозможны. `TileBand` рапортует минимум 0, натуральную — по спеке, и раскладывает плитки сам;
- при изменении `N` (ресайз окна) вид пере-нарезает строки; позиция прокрутки сохраняется по первому видимому элементу;
- `grouping=none` — прежний `Gtk.GridView` без изменений;
- виртуализация по строкам проверена пробой (`ListView` с высотами 28/90 px, `.tmp/grouping-probe/list.png`).

Почему не `FlowBox` на секцию: он строит виджет на каждый элемент — на 100k каталогах это OOM (спека 09 §7 требует виртуализацию).

### D7. «Столбцы»: колонка = секция

- `grouping=date`: одна колонка на секцию, сверху заголовок 28 px (label 13/600 secondary + count 12 mono muted, border-bottom), ниже — элементы этой группы;
- `grouping=none`: прежнее поведение — безголовые колонки по `ROWS_PER_COLUMN = 6`;
- длинная группа выше полосы: колонка растягивается, прокручивается вся полоса по вертикали (у `ListView` горизонтальная ось — основная, вертикаль остаётся у `ScrolledWindow`). Сворачивание/разбиение длинных групп на «продолжения» — вне итерации;
- ширина колонки — прежняя (натуральная, ограничена бюджетом символов).

### D8. Возможности и панель

- `DEFAULT_CAPABILITIES.grouping = True`; сборки без группировки (`capabilities.grouping=False`) не показывают секцию, `normalized()` по-прежнему откатывает `date → none` (честный UI, решение 4 в view-panel.md §2.4).
- новая настройка — модуль `view_panel/settings/grouping.py` + строка реестра; секция `SettingsSection.grouping = "Группировка"` ставится в реестре между «Режим просмотра» и «Сортировкой» (порядок секций — по первому вхождению, 03-layout §8).
- подписи радио — данные `display`: `Grouping.label` (`«По дате изменения»`, `«Без группировки»`), порядок `GROUPING_ORDER = (DATE, NONE)`.
- смена группировки — **без рескана**: вкладка собирает секции из уже загруженной модели и перерисовывает активный вид (как сортировка/скрытые, view-panel D5). Фейкового «Сканирование…» нет (D7 в view-panel.md §2.7).

### D9. Имена CSS-классов

| Класс | Назначение | Где рисуется |
|---|---|---|
| `.volna-group-header` | строка заголовка группы 28 px, фон/линия по 04 §6.2 | значки, столбцы |
| `.volna-group-title` | подпись группы 13/600 secondary | все режимы |
| `.volna-group-count` | счётчик группы 12 mono muted | все режимы |
| `.volna-dt-group` | ячейки групповой строки в «Подробностях» (фон `#26282d`, 28 px) | подробности |

Метрики переводятся через `px()` ([size.py](../src/volna/size.py)) и дублируются для `.volna-size-wide`, как у остальных видовых классов.

### D10. Сворачивание групп — не в этой итерации

Спека 04 §6.2 упоминает клик по заголовку со сворачиванием, 05 §3 — хранение `collapsed`. В `ViewSettings` такого поля нет (8 сохраняемых полей), а состояние «свёрнуто» требует новой схемы хранения. Это отдельная итерация; здесь заголовок — только подпись и счётчик. Зафиксировано осознанно, чтобы не протаскивать состояние через пресеты/стор задним числом.

## 3. Слои и зависимости

```
core/order.py       group_of, day_start, GroupBucket      (без изменений)
core/model.py       groups(): bucket + day, порядок       (правка)
display/grouping.py group_label(group) → str              (новый, без GTK)
display/settings.py Grouping.label, GROUPING_ORDER, caps  (правка)
tab.py              _sections(): модель → Section[]       (правка)
views/*.py          render(sections) группированно/флэт   (правки)
view_panel/...      секция «Группировка» → update()       (новый модуль + строка реестра)
```

Зависимости не меняются: `views` не импортирует `core`; `display` не импортирует `views`/GTK; вкладка — единственное место, знающее и `core`, и `views`, и `display`.

## 5. Поток при смене группировки

```
panel radio → update(grouping=...) → DirectoryTab.update_view_settings
  → settings.merged(capabilities) → normalized
  → self._settings = settings
  → _schedule_refresh() → _refresh() → _sections() → model.groups()/entries()
  → active_view.render(sections)
```

Рескан не запускается, `ScanState`, счётчики и выделение не меняются.

## 6. Хранилище

Схема не меняется: `grouping` уже в `settings.json` (`schema_version = 1`, [display/store.py](../src/volna/display/store.py)), миграция не нужна. Сохранённое `date` на сборке с `grouping=False` нормализуется в `none` (D8).

## 7. Тесты

### 7.1 Без дисплея (юнит)

- `core/model.py`: `THIS_WEEK` разбит по дням, дни — от новых к старым; `TODAY/YESTERDAY/OLDER/UNKNOWN` — по одной группе; `Group.day`; скрытые записи не попадают в группы.
- `display/grouping.py`: подписи всех корзин, имя дня недели, `UNKNOWN`; подпись не зависит от наличия GTK.
- `display/settings.py`: `grouping=True` в `DEFAULT_CAPABILITIES`; `normalized()` сборки без группировки; подписи `Grouping.label`.
- `tab._sections()`: плоская секция при `none`; N секций с заголовками при `date`; порядок и состав.

### 7.2 Виджеты (Xvfb)

- «Подробности»: групповые строки с label+count, порядок строк, активация заголовка ничего не открывает.
- «Значки»: заголовки секций и строки плиток; число плиток в строке зависит от ширины; ресайз пере-нарезает.
- «Столбцы»: заголовок у колонки-секции, счётчик; флэт-режим без заголовков.

### 7.3 Системные (не зависят от реализации)

- Каталог с известными `mtime`: окно → «Подробности» показывает заголовки групп в порядке Сегодня/Вчера/день/Неделю назад со счётчиками.
- Переключение режимов сохраняет группировку; «Без группировки» убирает заголовки во всех трёх режимах; повторное включение возвращает.
- Выбор группировки в панели «Вид» применяется к активной вкладке и переживает перезапуск (JSON).
- Сборка с `capabilities.grouping=False`: секции нет, вид флэт.
- Сортировка внутри группы: смена ключа не меняет состав/порядок групп, но меняет порядок внутри.

### 7.4 Нефункциональные (`slow`)

- 50k записей: включение группировки и переключение режима не блокируют UI дольше ~500 мс (отложено, как и в view-modes §7.4).

## 8. Риски и митигации

| Риск | Митигация |
|---|---|
| Ресайз в «Значках» пере-нарезает строки и сбрасывает прокрутку | сохранять первый видимый элемент и `scroll_to` после нарезки; тест на сохранение позиции |
| «Неделю назад» для записей многомесячной давности выглядит неточно | канон макета/спеки; формулировка группы — предмет отдельного решения, не блокирует итерацию |
| Группировка включена по умолчанию → меняется первый экран | это и есть канон макета (референс открыт с группировкой); откат — радио «Без группировки» |
| Длинная группа в «Столбцах» уводит полосу по вертикали | одно поведение на все группы; документировано, тест фиксирует отсутствие горизонтального разрыва |
| Календарные границы и DST | `day_start` через `localtime`/`mktime` уже корректен для календарных суток; 7-суточное окно — существующая формула |
| 100k каталог: O(n) на каждую перерисовку | как и раньше: перерисовка уже O(n) (склейка секций); нарезка строк добавляет O(n) без создания виджетов |
| Минимальная ширина окна в «Значках» с группировкой | `TileBand` не отдаёт минимальную ширину вверх (D6), пере-нарезка при ресайзе работает; тест `test_theme_lets_the_window_shrink_and_rechunk_the_bands` |

## 9. Критерии приёмки

### D11. Состояние — на вкладке, на сеанс

Свёрнутые группы — ключ-набор на вкладке: `DirectoryTab._collapsed_groups: set[str]`. Не входит в `ViewSettings`/JSON: новая вкладка начинает развёрнутой, перезапуск сбрасывает. Набор **переживает смену режима** («свернул Вчера в Подробностях → в Значках тоже свёрнуто»), в «Столбцах» игнорируется и **очищается при навигации** (состояние относится к листингу, а не к вкладке как таковой). Данные, а не код: тот факт, что «сворачивание» применимо к режиму, живёт в `display` рядом с метками режимов.

### D12. Ключ группы — семантический, в `display`

`group_key(Group) -> str` (рядом с подписями, D1): `today` / `yesterday` / `week:YYYY-MM-DD` (локальная дата дня) / `older` / `unknown`. Стабилен в пределах сеанса; день недели ключуется датой, поэтому не «съезжает».

### D13. Контракт: секция знает свой ключ и состояние

`Section` получает `key: str | None` и `collapsed: bool`; вид получает обратный вызов `on_group_action(key, GroupAction)` (`TOGGLE` / `COLLAPSE_OTHERS` / `COLLAPSE_ALL` / `EXPAND_ALL` — enum в `display`). Виды остаются отрисовщиками: что «свернуто», решает вкладка в `_sections()`; вид лишь прячет элементы свёрнутой секции и рисует интерактивный заголовок. Свёрнутая группа — заголовок с шевроном и сводкой, содержимое скрыто.

### D14. Взаимодействие

- Заголовок группы (вся строка-подпись) — переключение по клику; шеврон-кнопка слева от подписи показывает состояние (`down.svg`, свёрнуто — поворот −90°) и дублирует переключение; `aria`-метка «Свернуть группу»/«Развернуть группу». Шеврон — обычная `Gtk.Button`: фокус и клавиатура из инструментария.
- Правый клик по заголовку (в «Подробностях» — по любой ячейке полосы) — меню из трёх пунктов; чувствительность по текущему состоянию: «Свернуть остальные» — если групп больше одной, «Свернуть все» — если есть развёрнутые, «Развернуть все» — если есть свёрнутые. Стиль — как главное меню (`.volna-menu-*`).
- Позиция прокрутки при сворачивании не сохраняется намеренно: содержимое выше точки просмотра исчезает.

Уточнения, найденные при реализации:

- **Чувствительность меню считает вид, а не вкладка.** Отдельный заголовок не видит остальные группы, поэтому три флага («групп больше одной», «есть развёрнутые», «есть свёрнутые») вычисляются в `ListingView._read_menu_state()` из тех самых секций, которые вид сейчас рисует, и передаются в `GroupHeader.set_menu_state()`. Вкладка остаётся владельцем состояния (`_collapsed_groups`), вид — его проекцией (D13). Тесты: **320 passed** (было 305 до итерации; 15 новых системных в `tests/test_group_collapse.py`).
- **Клики по заголовку ловит вид, не заголовок.** `Gtk.ListView` (и `ColumnView` внутри) забирает правые клики в своей capture-фазе, поэтому обработчик на самом заголовке их не видит: меню не открывалось в «Значках» вовсе, а в «Подробностях» работало не по всей полосе. Решение: `ListingView._install_group_clicks()` ставит `Gtk.GestureClick` в `CAPTURE`-фазе на скроллер (он выше списка) и по `pick()` находит заголовок под курсором; полоса «Подробностей» — три ячейки, поэтому пустая `_NumericCell` несёт ключ группы и разрешается в заголовок через словарь вида. Левый клик по шеврону не перехватывается: это обычная кнопка и она отрабатывает сама.
- **Два контроллера, а не один.** `Gtk.GestureClick` с кнопкой по умолчанию (0) в этой сборке GTK получает только основную кнопку, поэтому правая кнопка вешается отдельным контроллером (`set_button(3)`); это и было причиной «меню работает только на кнопке».
- **Пункты меню по левому краю.** `Gtk.Button` центрирует свой label, поэтому пункт получает явный `Gtk.Label(xalign=0)`; текст меню читается как список, а не как ряд кнопок.
- **Сводка группы — тот же форматтер, что у шапки вкладки.** `views/format.format_counters()` и `core.counters_of()` общие для `window._update_active_status()` и `tab._sections()`; грамматика («1 папок») намеренно совпадает с шапкой.
- **`GroupHeader` несёт класс `.volna-group-header`.** Раньше его ставила только статичная подпись `header_box()` («Столбцы»); без него стили меню (`.volna-group-header .volna-menu-*`) не попадали на интерактивный заголовок.

Уточнения, найденные при реализации (поверх D1–D10):

- **«Значки», `TileBand`.** У GTK есть только *минимальная* ширина запроса: `Gtk.Box` с плитками замораживал минимальную ширину окна на текущей ширине полосы, и ресайз/пере-нарезка становились невозможны. Строка-полоса — свой `Gtk.Widget` с минимумом 0, натуральной шириной по спеке и ручной раскладкой плиток через `Gsk.Transform` (D6, §8).
- **«Значки», `TileBand` и время жизни плиток.** Плитки parentятся вручную (`set_parent`), и контейнера, который отпустил бы их, нет: освобождает их сама полоса — сразу при уходе из рутованного дерева (`do_unroot`, обычный путь) и по сигналу `destroy`, который GTK шлёт из своего `dispose` каждому виджету (гарантия на пути уничтожения: `unroot` приходит только рутованному виджету, а переопределить `dispose` из PyGObject нельзя). Без этого GTK финализирует полосу «still has children left» — предупреждение на каждом сворачивании/разворачивании групп (§12) — и плитки выброшенных строк утекают. Тест `test_discarded_bands_leave_no_children_behind` проверяет обе ветки в дочернем процессе: бросок нерутованной полосы (плитки обязаны финализироваться) и циклы сворачивания/разворачивания, затем stderr на отсутствие предупреждения.
- **«Подробности», сплошная полоса.** Adwaita даёт каждой ячейке `ColumnView` по 6 px паддинга, из-за чего фон групповой строки рвался «щелями». Компенсация `margin: 0 -6px; padding: 0 6px` на `.volna-dt-group` с комментарием о зависимости от темы; проверено в широком пресете и плотной раскладке.
- **«Значки», отступы.** Плитка во флэт-`GridView` несёт `margin-right` (в `GridView` нет gap); в полосе он обнулён и gap даёт `spacing`, поэтому межплиточный зазор равен спеке, а вертикальный остаётся.
- **Позиция прокрутки при пере-нарезке** сохраняется приближённо: GTK 4.14 не даёт `ALIGN_TOP` для `scroll_to`, поэтому якорь (первый элемент верхней строки) лишь возвращается в видимую область; на самом верху и при первой раскладке якорь не применяется, чтобы не увести заголовок группы.
- **`.store` режима «Значки»** — модель видимой презентации: плитки во флэте, строки в группировке. Это отражено в его докстроке; системные тесты читают пользовательские подписи, а не store.
- **«Группировка» по умолчанию включена** (`ViewSettings.grouping = DATE` + capability): первый экран теперь сгруппирован, как в каноническом макете; «Без группировки» возвращает прежний флэт. По этой причине обновлены ожидания в существующих тестах (без ослабления проверок).
- Вне итерации: 3 колонки «Подробностей» против 4-колоночной сетки спеки 04 §6.2 (было и до группировки), нефункциональный тест 50k. Сворачивание групп — реализовано следующей итерацией (§12).
